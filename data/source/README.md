# 数据维护

只手工维护 **maintenance.xlsx 和 song_placements.csv**。

maintenance.xlsx 是歌曲和共用资料的唯一来源。其余 9 张 CSV 与 display.json 是导入脚本生成的接口文件，data/normalized 是网站数据与核对结果。它们仍随仓库提交，但不要直接编辑；重新导入会覆盖这些生成文件。

## 日常新增歌曲

1. 打开 maintenance.xlsx 的「歌曲」页，在末尾添加一行。每首歌只填写一行，合作曲也不重复建歌。
2. 新歌的 song_id 留空，脚本会自动生成并回填；已有 ID 保持不变，改歌名时不要删除它。复制整行新增歌曲时，先清空复制过来的 ID。也可自行填写唯一 ID（仅限英文字母、数字、下划线、连字符）。
3. 填写名称、标签、已知站位、数字组合原文和实装日期。未知信息可留空；标签和歌名必填。
4. 在 song_placements.csv 添加歌名、分区和排序，song_id 可留空；脚本按唯一且完全相同的歌名关联并回填 ID。合作曲配置多行时会使用同一个 ID。已有非空 ID 不会按歌名重新匹配。
5. 保存并关闭 Excel，在项目根目录运行 `python scripts/import_maintenance.py`，或双击 preview.bat 生成并预览。

不需要安装 Python 第三方库。脚本使用 Python 3.10+ 标准库读取 .xlsx；不运行 Excel、不读取未保存的修改。只有新歌 ID 留空时，校验成功后才回填工作簿相应 ID 单元格；同一次操作也会回填展示顺序表的空 ID。其他工作簿内容与格式保留。

### 「歌曲」页字段

| 字段 | 填写方式 |
|---|---|
| song_id | 新歌留空自动生成；已有 ID 保留，与展示顺序表关联 |
| 歌曲名称 | 歌名，不能为空或重复 |
| 实装日期 | Excel 日期，或 YYYY-MM-DD / YYYY/MM/DD 文本；未知留空，不含时间 |
| 数字组合原文 | 原样保留重复，如 `12,12,34`；可用空格、中英文逗号分隔；按文本保存 |
| 标签（按顺序，用 \| 分隔） | 标签名称或 ID，如 `fine \| Trickstar`；顺序决定标签与合作曲分色顺序 |
| 1号位～10号位 | 人物简称或 ID；`自由` / `free` 表示通用站位；空白表示未录入 |
| 1号位标签～10号位标签 | 对应位置的标签名称或 ID，必须属于本首歌；不明确时可留空；位置为空时标签也须为空 |
| 特殊底色 | 可选的 #RRGGBB；空白时按组合／标签规则配色 |

组合标签名称取自「组合」页；独立分类名称取自「标签」页。公司归属由「歌曲标签 → 组合 → 公司」推导，不在每首歌上重复填写。引用可用唯一名称或 ID；名称有歧义时必须用 ID。使用名称引用时，更名需同步修改相关引用；使用 ID 引用则不受更名影响。

数字组合空白表示待录入，`无` 表示明确没有；`?` / `？` 保留为不确定标记。数字组合必须引用已填写的位置，当前仅支持 1–9 的单数字位置，不把 `10` 解释为第 10 位。

人物站位与组合成员名单分开维护。不能从组合名单推算歌曲站位；合作曲按全局 1–10 顺序填写。固定人物不能在同一首歌中重复；含「自由」的歌曲在具体成员筛选中整体排除，空格不等于自由对象。

实装日期导入后统一为 YYYY-MM-DD，不会改写 Excel。浏览器按日本时间判断：当天及过去日期用成员色底白字，空白／未来日期用白底成员色文字；仅作用于固定成员格，跨午夜自动刷新。

## 共用资料工作表

日常加歌可复用现有资料。只有新增或调整共用资料时才编辑下列工作表。

| 工作表 | 维护内容 | 自动生成文件 |
|---|---|---|
| 公司 | 公司／Other 的 ID、名称、类型、图标、顺序、代表色 | groups.csv |
| 组合 | 组合 ID、名称、代表色、图标、公司、父组合、类型、菜单顺序 | units.csv |
| 人物 | 人物 ID、唯一简称、代表色 | characters.csv |
| 组合成员 | 人物与组合的关系、组内顺序；同一人物可属于多个组合 | character_units.csv |
| 标签 | 标签 ID、对应组合；无组合时填写独立分类名称 | labels.csv |
| 次数颜色 | 数字组合次数区间及颜色 | frequency_colors.csv |
| 显示设置 | 人物统一字体与文字色 | display.json |
| 歌曲 | 歌曲基本资料、有序标签、实际站位、特殊底色 | songs.csv、song_labels.csv、positions.csv、display.json |
| 填写说明 | 使用说明，不参与导入 | — |

规则：

- 各数据页第 1 行固定表头，不要改名、合并单元格、写公式或增加数据列；新增记录可追加到现有 Excel 表格末尾，脚本也会读取表格范围以外的已填写行。筛选隐藏的行仍会导入。
- 实体 ID 保持稳定且唯一；公司、组合、人物关系字段可用对应的 ID 或唯一名称。代表色格式为 #RRGGBB。
- 「标签」有 unit_id 时 name 留空，显示名称由组合资料推导；无 unit_id 时填写分类名称。
- 新公司或组合的 icon_path 必须指向实际存在的仓库图片；含真实百分号的文件名保留原样。
- sort_order 为正整数。次数颜色区间从 1 连续覆盖，最后一个 max_count 留空，表示无上限。
- 「显示设置」只含 character_font_family、character_text_color 两个配置。特殊歌曲底色改在「歌曲」页维护。

## 展示分区与排序

song_placements.csv 继续单独维护，表头不变：

```text
song_id,title,section_id,section_name,sort_order
```

- song_id 引用「歌曲」页；新记录可留空并填写准确歌名，导入成功后自动回填。section_id 使用「组合」页的 ID，无组合的歌曲使用 group_other。
- sort_order 为正整数，越小越靠前，同一分区内不能重复；不要求连续，删除歌曲后无需重排全部序号。
- 每首歌至少有一个展示位置，同一歌曲与分区不能重复。合作曲可以在多个实际所属组合下分别设置顺序。
- title、section_name 只是阅读辅助列。权威名称来自 Excel。导入只补齐空 song_id，不改变现有 ID、展示分区或排序。
- CSV 使用 UTF-8（建议带 BOM）。Excel 编辑后保存为 CSV UTF-8，保留英文表头与 ID。

## 删除、导入与校验

删除歌曲：删除「歌曲」页的整行，并删除 song_placements.csv 中该 ID 的所有记录，再运行导入。关联标签、站位和特殊底色会自动清除；共用人物、组合与标签保留。

在项目根目录执行：

```powershell
python scripts/import_maintenance.py
python scripts/import_maintenance.py --check
npm run build
```

`python scripts/prepare_data.py` 是兼容入口，执行相同的导入流程；其 --check 同样检查 Excel、关联 CSV 和网站 JSON 是否同步。preview.bat 会先导入再启动预览。线上生效仍需提交源文件与生成结果并发布。

脚本先在临时目录校验整本 Excel 和展示顺序，成功后才更新生成文件。重复／非法 ID、未知成员／标签、非法日期、遗漏展示位置、重复序号等错误不会覆盖现有数据；--check 始终不写文件，也不会回填 ID。校验或写入失败不会留下部分回填结果；Excel 占用需要回填的工作簿或 CSV 时，请保存并关闭后重试。

更多规则见 [网站数据接口](../WEBSITE_DATA.md) 与 [开发说明](../../docs/DEVELOPMENT.md)。
